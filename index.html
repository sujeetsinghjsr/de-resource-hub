Scenario-based practice

Data Engineering interview prep

Try answering each question before revealing the guidance. Focus on trade-offs, failure handling, and how you would validate the result.

SQL · Data correctness
How would you identify duplicate records while keeping the latest record for each business key?
Reveal answer approach

Use ROW_NUMBER() over the business key, ordered by the update timestamp descending and a deterministic tie-breaker. Keep row number 1. Check null keys and equal timestamps, and validate the row counts before replacing the target data.

Spark · Performance
A Spark job is slow because one partition takes much longer than the others. What would you investigate?
Reveal answer approach

Check the Spark UI for skewed task durations and partition sizes. Inspect join keys and data distribution. Depending on the cause, consider broadcast joins, salting hot keys, adaptive query execution, or repartitioning. Compare runtime and shuffle metrics after each change.

Pipelines · Reliability
How would you make a pipeline safe to rerun after a partial failure?
Reveal answer approach

Use checkpoints or watermarks, deterministic transformations, idempotent writes, deduplication keys, and transactional or staged publishing where supported. Track run status and input boundaries, and test retries so a rerun does not double-count records.
